# 觅境 · 照片地点推断

## 目标

根据用户提供的单张照片，推断最可能的拍摄地点，输出地点名称、证据等级与可核对证据。

## 输入

- `photo`（string，必填，1–20000000 字）：照片的 base64 data URL 或可公开访问的图片地址。
- `hint`（string，可选，0–200 字）：用户补充的拍摄线索，可信度未知，必须与画面交叉验证。

## 输出

- `place`（string，≤120 字）：最可能的地点名称，形如「地点 行政区」；无法定位时为空字符串。
- `confidence`（string，枚举：`high` / `medium` / `low`）：证据等级。
- `evidence`（string）：逐条证据，每行一条，必须写明在看画面里看到了什么。
- `status`（string，枚举：`ok` / `missing_model` / `unlocatable`）：执行状态。

## 流程

1. 读取 `photo` 与 `hint`；`photo` 为空或不是图片地址，由输入 schema 拦截，不进入流程。
2. 观察画面：提取建筑形态与材质、牌匾或招牌原文、道路走向、水系、植被、地形、车辆类型；每条只写看到了什么，不下结论。
3. 生成候选：给出 1–4 个候选地点，按可能性排序；能识别到街区级就写街区全名，不叠加国家与省份，不用括号或斜杠并列多个地点。
4. 收敛候选：逐个审查画面特征是否真的支撑该候选，支撑不足的直接删除，保留不超过 3 个。
5. 评估等级：至少两类独立依据（如牌匾文字 + 建筑特征）判 `medium`；强特征且有文字互证判 `high`；仅有单一模糊依据判 `low`。
6. 组装输出：按 `output_schema` 输出 `place`、`confidence`、`evidence`、`status`。

## 边界

- 不编造街景比对、地图核实或经纬度；本制品不产坐标，坐标能力由外部取证流程提供。
- 不把「看起来像」写成结论；每条证据必须写明具体看到了什么。
- 不处理视频、多图对比、纯室内特写与无明显地面信息的输入，这类输入判 `status:"unlocatable"`。
- 不输出概率数值、不声称「已核实」、不给超出画面证据的精度。

## 失败处理

- `photo` 为空或超长 → 输入 schema 拦截，不进入流程。
- 模型未绑定（`dfs.json.model.model` 为空）→ 运行前直接失败，提示先用 `dfs model` 配置端点与模型。
- 所有候选均缺乏画面支撑 → `status:"unlocatable"`，`place` 留空，不降级猜测。
