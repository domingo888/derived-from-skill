# 术语表

## 核心术语

### Skill 规约（Skill Specification）

描述一类任务「要什么」的文本与结构化契约，包括目标、输入输出、流程、边界、失败处理。**它是规约，不是执行脚本**：本身不被直接解释运行，而是作为编译输入。

### DFS（Derived From Skill / 技能衍体）

以声明式 Skill 规约为源素材，经模型理解、转化、衍生生成运行逻辑的独立可运行制品。

- 自带最小运行时，无需 Agent 宿主；
- 模型只在编译期决定「怎么走」，运行期只做节点内推理；
- 不具备跨 Skill 的自主调度能力。

### Skill Capsule（技能胶囊）

Skill 执行合约被**静态固化**、打包即可直接解释执行的制品。与 DFS 的对照：

| 维度 | Skill Capsule | DFS |
| --- | --- | --- |
| Skill 的地位 | 最终执行合约 | 源规约 / 素材 |
| 流程何时确定 | 打包时，人工固定 | 编译时，模型生成 + 校验 |
| 运行期是否解释 Skill 文本 | 是（或按固定合约执行） | 否（只执行 plan） |
| 柔性 | 低（改流程需重打包） | 中（规约内可适配分支） |
| 确定性 | 最高 | 高（计划锁定后） |
| 适用 | 流程绝对固定、强合规 | 需少量分支适配的专业任务 |

### transform / 编译

把规约转成可执行计划的工序。只在制品构建时发生一次，产物为 `plan.json`。

### plan（运行计划）

编译产物：有序步骤、提示模板、分支与输出映射。运行期只读，不可被运行时修改。

### fail closed

契约不满足时直接失败，不做降级猜测、不自动换模型、不自动放宽 schema。

---

## 对照概念（避免混淆）

| 术语 | 实际含义 | 与 DFS 的区别 |
| --- | --- | --- |
| Agent | 自主规划的调度器，动态决定调用哪个能力 | DFS 无调度层，自由度在编译期一次性消耗 |
| Multi-Agent / MoA | 多个 Agent 协商、投票、互相反思 | DFS 不涉及多智能体协商 |
| Plugin / Tool | 供宿主调用的函数或扩展 | DFS 是应用，不是插件 |
| LLM Workflow | 固定流程的大模型应用 | 概念相近，但 DFS 强调「由 Skill 规约编译而来」且强制契约校验 |
| MCP Server | 对外暴露工具的服务协议 | DFS 可暴露为 MCP，但内部是完整流程而非单一工具 |
| RAG | 检索增强生成 | 无关；DFS 不依赖检索管线 |

## 命名约定

- 主仓库：`derived-from-skill`（全称，避免 `DFS` 与深度优先搜索/分布式文件系统混淆）
- 子项目：`dfs-<skill-name>`，例如 `dfs-invoice`
- 制品内固定文件名：`SKILL.md`、`dfs.json`、`plan.json`
- 运行产物目录：`runs/`（不入库，`.gitignore` 已排除）
