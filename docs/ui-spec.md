# R2 独立 UI 规范（Interface）

> 一句话：**每个 DFS 制品都必须自带一份独立界面，形态按项目情况选 web 或 window，不允许「只有命令行、让用户自己拼 JSON」。**

DFS 的定位是「把 Skill 变成应用」。应用的标志之一，是**非开发者也能用**。一个只能靠 `curl` 和手写 JSON 驱动的制品，本质仍是脚本。

---

## 1. 硬性要求

`dfs.json` 的 `ui` 是**必填**字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `kind` | ✅ | `web`（浏览器） / `window`（独立窗口） / `none`（仅库型，需在 `note` 说明理由） |
| `title` | 推荐 | 界面标题，默认取制品 `title` |
| `host` | 可选 | 仅 web，默认 `127.0.0.1`，**禁止 0.0.0.0** |
| `port` | 可选 | 仅 web，默认 `8787`，范围 1024–65535 |
| `width` / `height` | 可选 | 仅 window，默认 760×620 |
| `entry` | 可选 | 自定义页面路径（当前内置 UI 未接入自定义页面，会在启动时告警） |

`kind: "none"` 仅允许用于**被其他程序调用的库型制品**（例如纯批处理组件），并且必须在 `note` 写明原因。

---

## 2. 两种形态，同一套行为

| 形态 | 启动命令 | 壳体 | 适用场景 |
| --- | --- | --- | --- |
| `web` | `python dfs.py serve <制品>` | 浏览器标签页 | 局域网内多人本地使用、需要并存多个页面 |
| `window` | `python dfs.py window <制品>` | 无标签栏的独立应用窗口（浏览器 app 模式） | 单任务交付、给非技术用户、需要「像软件一样」的观感 |

关键设计：**两种壳体共用同一份页面与同一条执行路径**（`webui` 的页面 + `runner.run_once`）。因此：

- 窗口版有的能力，浏览器版一定有；
- 行为不存在「窗口能跑、网页不能跑」的分叉；
- 只需要维护一套 UI 代码。

可选增强：`python dfs.py window --native` 用 tkinter 渲染原生窗口。该路径依赖系统 Tcl/Tk，**不是默认路径**（部分 Python 运行时缺失 Tcl，例如本项目开发机上的沙箱运行时）。

---

## 3. 界面必须包含的要素

一个合规的制品界面至少要有：

1. **输入区**：由 `io.input_schema` 自动生成，字段顺序与 schema 属性顺序一致；
2. **运行按钮**：一次点击完成一次执行，不需要用户理解 plan；
3. **结果区**：展示 `io.output_schema` 校验通过的输出；
4. **错误区**：**原文展示**失败原因，不美化、不吞错、不给出「已尽力」的模糊结论；
5. **证据位置**：显示本次运行的 `runs/<运行ID>/` 目录，便于复核；
6. **身份信息**：制品名、版本、Skill 来源、模型绑定与鉴权状态。

---

## 4. 表单生成规则

- **不得手写字段列表**：字段必须从 `input_schema` 推导，保证「契约改了，界面自动跟着改」。
- 类型映射：`string` → 文本框（`format: text` 或长文本用多行）；`integer` / `number` → 数字框；`boolean` → 勾选框；`enum` → 下拉；`array` → 多行文本（按换行或逗号切分）。
- 必填字段标 `*`，缺失时在提交前拦截，报错信息包含字段名。
- 前端提交原始值，**类型转换与校验交给运行时**（`uigen.coerce_input`），避免前端与后端两套校验规则打架。

---

## 5. 安全边界

1. 默认只监听 `127.0.0.1`，不对外暴露；
2. 不带任何账号体系（本地单用户场景），因此**禁止绑定公网地址**；
3. 不提供文件上传、命令执行、任意 URL 代理等能力；
4. 执行失败一律返回错误原文，不返回堆栈中的敏感路径以外的信息（`runs/` 路径可以返回，因为它就是证据位置）。

---

## 6. 验收清单

发布一个制品前，逐项确认：

- [ ] `dfs.json` 有 `ui.kind`，且与实际交付形态一致
- [ ] `python dfs.py serve`（或 `window`）能启动，页面可打开
- [ ] 表单字段与 `input_schema` 完全一致（不多、不少）
- [ ] 正常输入能出结果；非法输入能显示明确错误（字段级）
- [ ] 每次运行都能在 `runs/` 找到对应证据
- [ ] 页面顶部能看到制品名、版本、来源、模型与鉴权状态
- [ ] 窗口模式下，关闭窗口后本地服务随之停止（无残留进程）
